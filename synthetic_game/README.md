# `synthetic_game/` — the synthetic Conservation Security Game (Appendix B.1)

Reproduces Appendix B.1 of *Strategic Decision Focused Learning*: a synthetic
security game on a 10 x 10 grid (N = 100 cells, catch penalty 10) whose animal
densities are Gaussian blobs, sparse spikes or concentric rings, observed only
through sparse noisy survey sweeps; a four-layer CNN predictor; and the four
methods PTO, ZOC, KKT and Hybrid trained with the Huber loss and AdamW on
1,000 synthetic scenarios for 200 epochs. Its figures are the regime panels
`regime_panel_4row`, `regime_panel_hybrid_kkt` and `regime_panel_failures`.

No data is needed: every scenario is generated by the script itself.

## Files

| File | What it is |
|---|---|
| `grid_experiment.py` | The experiment: data generation, CNN, Stackelberg solvers, the four training procedures, evaluation and diagnostic plots. One run per training seed. |
| `plot_regime_panels.py` | Draws the regime panels of Appendix B.1 (and ten single-scenario panels) from a finished run's saved weights and test scenarios. |
| `utils.py` | `best_device()` / `log_device()` (CUDA > Apple MPS > CPU). |
| `../results/paper/synthetic/` | The paper's run: `summary.txt`, `results.csv`, `obs_test.npy`, `den_test.npy` and the weights `pto_model.pth`, `zoc_model.pth`, `kkt_model.pth`, `hyb_model.pth`. |

Both scripts explain their pipeline, outputs and arguments in their module
docstrings (`python grid_experiment.py --help`).

## The paper's run

The stored run (`results/paper/synthetic/summary.txt`) used exactly these
settings, all of which are the `grid = 10` entry of `GRID_CONFIGS` in
`grid_experiment.py`:

| Setting | Value |
|---|---|
| grid | 10 x 10 (N = 100 cells), catch penalty 10 |
| scenarios | 1,000 generated for training (split 800 train / 200 validation), 30 test |
| survey sweeps | 5 sweeps per scenario, 20 cells each, counts ~ Poisson(2 x density) |
| epochs | 200, window / regime length `n_store` = 20 |
| optimiser | AdamW, lr 3e-3, weight decay 1e-4, cosine schedule, Huber loss, grad-clip 1 |
| KKT / Hybrid | 32 scenarios per epoch in batches of 4; cvxpylayers (SCS, eps 1e-2) |
| data seed | 42 (the test scenarios regenerate identically from it) |
| device | Apple MPS; PTO 9 s, ZOC 6 min, Hybrid 8 min, KKT 10 min (25 min in all) |

To run it:

```bash
python grid_experiment.py --grid 10 --seeds 1 --epochs 200
```

(`--epochs 200` is already the grid-10 default and may be omitted.) The output
goes to `output/grid10_seed1_<timestamp>/` next to the script; use `--out` to
put it elsewhere. Note that the appendix's "1,000 scenarios, 200 epochs"
describes this stored run; an older README in the original code suggested
`--seeds 5 --epochs 500`, which is not what produced the paper's figures.

Two caveats on exact reproduction. (1) The stored run was made before the
`--seeds` loop existed, so its training seed was not recorded; the script's
module default `SEED = 42` is the likeliest, and `--seed-start 42 --seeds 1`
runs that seed. (2) Training on a GPU or on MPS is not bit-reproducible
(dropout and reductions), so re-training will not give identical weights or
exactly the same per-scenario winners. The stored weights are provided so the
paper's panels can be regenerated exactly (next section).

Smoke test (about 20 seconds, a 2 x 2 grid):

```bash
python grid_experiment.py --grid 2 --seeds 1 --epochs 5 --out /tmp/grid_smoke
```

## The regime panels

```bash
python plot_regime_panels.py                       # from results/paper/synthetic
python plot_regime_panels.py --run-dir <run folder> --out <folder>
```

Writes `regime_panel_4row.png`, `regime_panel_hybrid_kkt.png`,
`regime_panel_failures.png` and `compare_sc<N>_<winner>.png` for the ten
scenarios they were chosen from (by default into `output/regime_panels/` next to the script). Each row is
Ground Truth | PTO | ZOC | KKT | Hybrid; the winner is green, and the utility
below each panel is that of the SSE strategy computed from the method's
prediction, evaluated against the true density.

The scenario numbers are hard-coded for the paper's stored run; they were
read off the `winner` column of its `results.csv`. For a new run, pick new
ones from its `results.csv` and `compare_panels/` (one panel per scenario is
written there by `grid_experiment.py`). The stored run saved Hybrid's weights
as `hyb_model.pth`; the current script writes `hybrid_model.pth`, and
`plot_regime_panels.py` accepts either.

## Outputs of `grid_experiment.py`

One folder per run, `<out>/grid<N>_seed<s>_<timestamp>/`:

```
summary.txt                      utility and MAE tables, gaps to optimal, win rates
results.csv                      one row per test scenario: utilities, winner, gaps, MAE
pto_model.pth zoc_model.pth kkt_model.pth hybrid_model.pth   weights (saved as each finishes)
pto_results.csv ... hybrid_results.csv                        per-model utility and MAE
obs_test.npy den_test.npy        the test scenarios (inputs and true densities)
heatmap_panel.png                truth / input / predictions / strategies for 5 scenarios
utility_bar.png utility_violin.png utility_scatter.png gap_to_optimal.png
compare_panels/                  compare_sc<N>.png per scenario, regime_top6.png, wins_<method>.png
```

With `--seeds K > 1` a `summary_grid<N>_<K>seeds.txt` with the across-seed
table is written to `<out>/` as well.

## Requirements

`torch`, `numpy`, `scipy`, `matplotlib` (see the repository's
`requirements.txt`); `cvxpy` and `cvxpylayers` for KKT and Hybrid — without
them both fall back to ZOC with a warning, so install them to reproduce the
appendix. The Stackelberg LPs run on the CPU whatever the device.
